Case 1 — EC経理計算の月次自動化

使用技術
Excel VBA
問題の構造
「毎月同じ手順を踏んでいる」のに、その手順が属人化・非明文化されていた。担当者が変わるたびに引き継ぎコストが発生し、入力ミスのリスクも消えない構造。
背景
エンタメ会社の国内外向けECサイトでは、月次の経理計算が複数シートにまたがる手作業で行われており、担当者の工数と入力ミスのリスクが課題でした。
対応
まず処理フロー全体を可視化し、「毎回必ず同じ手順を踏む工程」を特定。売上データの集計・通貨換算・帳票出力までの一連をExcel VBAでマクロ化し、月次ルーティンをボタン一つで完結できる仕組みに置き換えました。
成果
毎月発生していた手作業の繰り返しを排除。担当者が変わっても同じ品質で処理できる体制を整えました。

Case 2 — ExcelデータのAccess / Notion移行提案

使用技術
Excel / Access / Notion / プロセス設計
問題の構造
「Excelで管理している」という事実の裏に、「複数人が同じファイルを触る」「バージョンが乱立する」「検索できない」という複合的な問題が埋もれていた。ツールの問題ではなく、データ構造とアクセス設計の問題。
背景
書籍流通業界においてデータがExcelファイルで管理されており、検索・更新・共有のたびに手間がかかっていました。複数人が同じファイルを触ることによる上書きリスクも問題でした。
対応
データ構造を分析し、「誰が」「何の目的で」「どのくらいの頻度で」使うかを整理。利用頻度・共有範囲・操作スキルに応じてAccessとNotionの2案を提案し、業務フロー全体を再設計した上で移行を主導しました。
成果
3日かかっていた作業を半日に短縮。データの重複・上書きリスクもゼロに。「ツールを変えた」のではなく「仕組みを変えた」結果です。

Case 3 — 30,000件データクリーニングの自動化

使用技術
Python
問題の構造
「データが汚い」という状況の背後に、どの種類のエラーがどれだけ存在するかが不明だった。パターンを把握せずに作業を始めると、手作業でも自動化でも対応漏れが生まれる。
背景
友人からの依頼で、30,000件規模のデータクリーニングが必要な状況に。手作業で対応した場合、60〜100時間の工数が見込まれていました。
対応
最初にデータ全体をスキャンしてエラーパターンを網羅的に洗い出し、それを元にPythonでデータ検証・クレンジング・整形の処理を自動化するスクリプトを設計・実装しました。
成果
手作業60〜100時間の処理を約5時間で完了（95%削減）。均一な品質で処理できるため、後続工程のエラーも減少しました。

Case 4 — AI活用研修の設計・実施

担当
研修設計・講師・資料作成
問題の構造
「AIを使えばいい」という方針はあるが、「何から始めるか」「どこまで任せられるか」が整理されていない状態。ツールを渡しただけでは定着しない。
背景
社内でAI活用を推進する立場として、ツールに不慣れなメンバー・経営層への導入支援が必要でした。単なる操作説明では定着しないため、業務との接続まで設計する必要がありました。
対応
参加者の業務内容と習熟度を事前にヒアリングし、「この業務のこの工程なら任せられる」という具体的なユースケースを起点にカリキュラムを設計。ハンズオン形式で実際に手を動かしながら学ぶ構成にしました。
成果
受講後に「すぐ使える」と感じてもらえる定着率を目標に設計。抽象的な説明ではなく、自分の業務に引き寄せた理解が進む研修として実施しました。
